# 배포 과정 - 현재 서버 확정안 (GHCR)

```text
git push main
 -> GitHub Actions
 -> React + Spring Docker image build
 -> FastAPI Docker image build
 -> GHCR push (commit SHA)
 -> SSH :22
 -> C:\home\dahum\app
 -> git pull --ff-only
 -> deploy.ps1
 -> Docker Desktop 확인
 -> MariaDB backup
 -> docker compose pull
 -> docker compose up -d
 -> health check
 -> Dahum Caddy :9000
 -> 기존 MOVEAI Caddy :443
 -> https://yellow.it.kr
```

## 최초 1회

1. `yellow.it.kr` A record가 서버 공인 IP를 가리키는지 확인
2. 기존 MOVEAI Caddyfile에 `deploy/caddy/moveai-yellow.it.kr.caddy.example` 블록 추가
3. `C:\home\dahum\app`에 `EST-AI-Challengers-31/saver` clone
4. `C:\home\dahum\runtime\.env` 생성
5. GitHub Actions Secrets 등록
6. `main` push 또는 `workflow_dispatch` 실행

## 일반 배포

미니PC에서는 application image를 build하지 않는다. GitHub Actions가 만든 SHA image를 pull하고 실행한다.

## 성공 기준

- GitHub Actions의 두 image build/push 성공
- SSH 배포 성공
- Dahum Caddy host 9000 응답
- Spring health 정상
- FastAPI health 정상
- MariaDB healthy
- `https://yellow.it.kr` 화면 로딩

## 절대 금지

- `docker compose down -v`
- Dahum에서 80/443 재점유
- runtime `.env` 삭제/덮어쓰기
- 서버에서 운영 image를 임의 build해서 Actions 배포본과 섞기
- Action에서 MOVEAI Caddyfile을 매번 자동 변경
