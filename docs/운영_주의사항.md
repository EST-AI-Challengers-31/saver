# 운영 주의사항

## 1. 가장 위험한 항목

- 실제 Secret Git commit
- DB volume 삭제
- 3306/8000 외부 공개
- OAuth callback proxy 누락
- UNKNOWN을 SAFE로 표현
- 가족 권한 누락(IDOR)
- 부모 동의 없는 지속 데이터 수집

## 2. 매 배포 전

- DB 변경 있는지 확인
- migration 있으면 backup
- `.env` key 추가 여부 확인
- OAuth redirect URL 변경 여부 확인
- Caddy route 변경 여부 확인

## 3. 매 배포 후

- compose status
- DB health
- backend health
- frontend
- Kakao/Google login
- 분석 API
- 로그에 secret/token 노출 없는지 확인

## 4. 로그

권장 보존:
- requestId
- event type
- error code
- latency

피해야 할 로그:
- OAuth access token
- raw invitation token
- screenshot binary/path 장기 기록
- DB password
- full `.env`

## 5. 발표 당일

- 운영 DB schema 변경 최소화
- demo account/family 미리 확인
- 직접 입력 fallback 준비
- LLM fallback template 준비
- network 장애를 대비한 mock/demo 전략은 팀 내부에서 별도 준비

단, 실제 서비스처럼 보이게 허위 탐지 결과를 조작하지 않습니다. synthetic demo라면 demo임을 내부적으로 구분합니다.
