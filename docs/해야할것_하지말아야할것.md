# 해야 할 것 / 하지 말아야 할 것

이 문서는 구현 중 의견이 갈릴 때 우선 확인하는 기준입니다.

## 1. Frontend

### 해야 할 것
- 모바일 우선 UI
- `/api/me`로 인증 상태 확인
- 가족/분석 대상 명확히 표시
- OCR 수정 UI 또는 직접 입력 fallback
- HIGH/MEDIUM/UNKNOWN 정확히 표현
- 안내문 복사

### 하지 말아야 할 것
- React에서 판정
- OAuth secret 저장
- FastAPI 직접 호출
- UNKNOWN을 안전 표시
- raw LLM HTML 직접 렌더링

## 2. Spring Boot

### 해야 할 것
- 인증/가족 권한의 source of truth
- provider + subject로 social identity 관리
- 가족 API에서 membership 검증
- AI 응답 validation
- DB transaction
- requestId 기반 로그

### 하지 말아야 할 것
- controller 한 파일에 전체 로직 구현
- 이메일 같은 값만 보고 OAuth 계정 자동 병합
- familyId를 클라이언트가 보냈다고 권한 있다고 가정
- secret을 response/log에 출력

## 3. FastAPI

### 해야 할 것
- exact -> similarity -> unknown 순서
- 근거 반환
- LLM은 설명에만 사용
- template fallback

### 하지 말아야 할 것
- LLM 단독 판정
- no match를 SAFE로 반환
- 인터넷에 8000 공개
- 인증/가족 로직 중복

## 4. MariaDB

### 해야 할 것
- UUID application 생성
- family role은 membership에 저장
- social identity 분리
- migration으로 변경
- backup 후 schema 변경

### 하지 말아야 할 것
- 운영 DB에 init SQL 재적용
- raw invite token 저장
- OAuth Client Secret 저장
- 개인정보를 필요 이상 수집

## 5. 가족/개인정보

### 해야 할 것
- 초대/수락
- 만료/revoke
- 연결 동의
- 연결 해제 고려

### 하지 말아야 할 것
- 부모 동의 없이 지속 감시
- 전체 연락처/SMS 수집
- 가족이면 모든 데이터 무조건 공유

## 6. 배포

### 해야 할 것
- `C:\home\dahum\app` Git
- `C:\home\dahum\runtime` 운영 데이터
- 80/443 Caddy
- 22 SSH 최소 노출
- 3306/8000 외부 비공개
- `.env` Git ignore
- DB backup

### 하지 말아야 할 것
- 실제 비밀번호를 GitHub workflow/MD에 하드코딩
- MariaDB port forwarding 외부 공개
- `docker compose down -v`를 일반 배포에서 실행
- DB volume 삭제를 자동화
