# 내가 해야 할 부분 — 첫 자동배포 체크리스트

이 파일은 **EST-AI-Challengers-31/saver 저장소에 코드를 올린 뒤 GitHub Actions로 Windows 미니PC에 자동배포하기 위해 사용자가 직접 해야 하는 작업만** 정리한 문서입니다.

## 0. 확정된 배포 기준

- 서버 OS: Windows
- Windows 계정: `home`
- 서버 프로젝트 경로: `C:\home\dahum\app`
- 서버 런타임 경로: `C:\home\dahum\runtime`
- GitHub 저장소: `EST-AI-Challengers-31/saver`
- 배포 브랜치: `main`
- Java: **21**
- Spring Boot: 3.x
- React: Vite + TypeScript
- FastAPI: Docker 내부 `8000`
- MariaDB: Docker 내부 `3306`
- 닿음 호스트 진입 포트: `9000`
- SSH: `22`
- 기존 MOVEAI Caddy: 호스트 `80/443`
- 공개 도메인: `https://yellow.it.kr`
- 앱 이미지 빌드 위치: GitHub Actions
- 이미지 저장소: GHCR
- 미니PC 역할: 이미지 Pull + 컨테이너 실행

## 1. saver 저장소에 이 ZIP의 내용을 넣기

ZIP 안의 최상위 파일/폴더를 `saver` 저장소 루트에 그대로 넣습니다.

반드시 다음 파일이 저장소에서 보여야 합니다.

```text
.github/workflows/deploy.yml
frontend/
backend/
ai/
db/
deploy/
docs/
README.md
```

그 다음:

```bash
git add .
git commit -m "chore: initialize Dahum auto deployment"
git push origin main
```

> `main` push가 바로 Actions를 실행하므로, 아래 2~5번을 먼저 준비한 다음 push하는 것을 권장합니다.

## 2. GitHub Actions Secrets 등록

GitHub 저장소에서:

`Settings → Secrets and variables → Actions → Repository secrets`

다음 4개를 등록합니다.

```text
SERVER_HOST      = 미니PC 공인 IP
SERVER_USER      = home
SERVER_PASSWORD  = 실제 SSH 비밀번호
SERVER_PORT      = 22
```

비밀번호는 코드, README, `.env.example`에 넣지 않습니다.

## 3. GitHub Actions Variable 등록 (선택)

`Settings → Secrets and variables → Actions → Variables`

선택적으로:

```text
SERVER_APP_PATH = C:\home\dahum\app
```

등록할 수 있습니다. 등록하지 않아도 workflow 기본값이 `C:\home\dahum\app`입니다.

## 4. 서버 저장소 최초 1회 준비

GitHub Actions는 서버 경로에 이미 `saver` 저장소가 clone되어 있다고 가정합니다.

미니PC PowerShell에서 확인:

```powershell
Test-Path C:\home\dahum\app\.git
cd C:\home\dahum\app
git remote -v
git branch --show-current
```

`origin`이 `EST-AI-Challengers-31/saver`이고 브랜치가 `main`이어야 합니다.

아직 clone하지 않았다면 저장소 권한에 맞는 방식으로 **최초 1회만** clone합니다.

```powershell
New-Item -ItemType Directory -Force C:\home\dahum | Out-Null
cd C:\home\dahum
git clone <saver 저장소 clone URL> app
```

## 5. 서버 runtime `.env` 최초 1회 작성

저장소의:

```text
deploy/.env.example
```

을 참고해서 서버에 다음 파일을 만듭니다.

```text
C:\home\dahum\runtime\.env
```

필수 핵심값:

```text
DAHUM_RUNTIME=C:/home/dahum/runtime
DAHUM_HOST_PORT=9000
PUBLIC_DOMAIN=yellow.it.kr
PUBLIC_BASE_URL=https://yellow.it.kr

MARIADB_IMAGE=mariadb:11.4
MARIADB_DATABASE=dahum
MARIADB_USER=<원하는 DB 사용자>
MARIADB_PASSWORD=<강한 비밀번호>
MARIADB_ROOT_PASSWORD=<위와 다른 강한 비밀번호>

SPRING_DATASOURCE_URL=jdbc:mariadb://mariadb:3306/dahum
SPRING_DATASOURCE_USERNAME=<MARIADB_USER와 동일>
SPRING_DATASOURCE_PASSWORD=<MARIADB_PASSWORD와 동일>
AI_BASE_URL=http://ai:8000
SERVER_FORWARD_HEADERS_STRATEGY=framework
```

현재 smoke-test 코드에서는 OAuth/OCR/LLM/Pinecone을 실제 호출하지 않으므로 관련 값은 임시 placeholder여도 배포 연결 확인은 가능합니다. 실제 기능을 붙이기 전에 반드시 실제 secret으로 교체합니다.

## 6. 기존 MOVEAI Caddy에 도메인 라우팅 최초 1회 추가

기본 설정은 `OUTER_CADDY_AUTO_CONFIGURE=false`이므로 닿음 배포가 MOVEAI 저장소를 자동 수정하지 않습니다.

`C:\MOVEAI\Caddyfile`에 **최초 1회** 아래 블록을 추가합니다.

```caddy
yellow.it.kr {
    encode zstd gzip
    reverse_proxy host.docker.internal:9000
}
```

기존 MOVEAI 블록은 삭제하거나 수정하지 않습니다.

추가 후 Caddy 설정을 validate/reload합니다. 가능하면 이 변경은 MOVEAI 저장소에도 커밋해서 `C:\MOVEAI`가 dirty 상태가 되지 않게 유지합니다.

## 7. 가비아 DNS 확인

`yellow.it.kr`의 A 레코드가 미니PC 공인 IP를 가리켜야 합니다.

미니PC 또는 로컬 PC에서:

```powershell
Resolve-DnsName yellow.it.kr -Type A
```

공인 IP가 맞으면 됩니다. DNS에는 `9000`을 적지 않습니다.

## 8. 첫 Actions 실행

모든 준비 후 `main`에 push하거나 GitHub Actions 화면에서 `workflow_dispatch`로 수동 실행합니다.

정상 흐름:

```text
Checkout
→ backend(React+Spring) 이미지 build
→ FastAPI 이미지 build
→ GHCR push
→ SSH 22
→ server git pull
→ GHCR login
→ MariaDB backup(기존 DB가 있을 때)
→ docker compose pull
→ docker compose up -d
→ /api/system/status health check
→ success
```

## 9. 첫 배포 성공 후 확인

미니PC:

```powershell
docker ps --format "table {{.Names}}\t{{.Ports}}\t{{.Status}}"
```

예상되는 닿음 컨테이너:

```text
dahum-caddy-1
dahum-backend-1
dahum-ai-1
dahum-mariadb-1
```

로컬 게이트웨이 확인:

```powershell
Invoke-RestMethod http://127.0.0.1:9000/api/health
Invoke-RestMethod http://127.0.0.1:9000/api/system/status
```

브라우저:

```text
https://yellow.it.kr
```

## 10. 평소 개발할 때

정상 배포가 한 번 끝난 뒤에는 보통 다음만 하면 됩니다.

```bash
git add .
git commit -m "feat: ..."
git push origin main
```

프론트/백엔드/AI 코드가 바뀌면 Actions가 새 이미지를 만들고 미니PC가 정확한 commit SHA 이미지를 pull해서 교체합니다.

## 건드리지 말아야 할 것

기능 개발 중 특별한 이유 없이 다음을 수정하지 않습니다.

- `.github/workflows/deploy.yml`
- `deploy/docker-compose.yml`
- `deploy/scripts/*.ps1`
- `backend/Dockerfile`
- `ai/Dockerfile`
- `deploy/caddy/Caddyfile`
- 서버의 `C:\home\dahum\runtime\.env`
- 기존 MOVEAI의 컨테이너/볼륨/네트워크

단, Java/Node/Python 버전 변경, 새로운 컨테이너 추가, 새로운 환경변수 추가 같은 **인프라 변경이 명확히 필요한 경우에는** 위 파일도 변경해야 합니다.
