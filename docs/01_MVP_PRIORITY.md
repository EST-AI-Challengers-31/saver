# 01. MVP 우선순위

이 문서는 기획서/PPT의 핵심 데모에, 현재 팀이 추가로 확정한 **모바일 소셜 로그인 + 최소 가족 연결**을 포함한 구현 우선순위입니다.

## P0 - 데모 전에 무조건 완성

### 1. 모바일 접속/로그인

- 모바일 React 화면
- Kakao 로그인
- Google 로그인
- `/api/me`
- 로그아웃

로그인 자체를 보여주는 데 시간을 과도하게 쓰지 말고, 분석/가족 흐름에 들어가기 위한 최소 인증으로 구현합니다.

### 2. 가족 연결 최소 기능

- 가족 1개 생성
- 현재 사용자 역할 생성
- 부모 초대 링크
- 초대 수락
- 분석 대상 가족 구성원 선택
- 다른 가족 접근 차단

복잡한 관리자 권한/승인 단계는 제외합니다.

### 3. 입력

- 스크린샷 업로드
- 앱 이름 직접 입력
- 업로드 실패/빈 입력 검증
- OCR 결과 수정 가능

### 4. 판정

- 정확 일치 DB 조회
- 유사도 검색
- HIGH / MEDIUM / UNKNOWN
- 판정 근거

### 5. 설명

- 자녀용 상세 근거
- 부모용 쉬운 설명
- 지금 해야 할 행동

### 6. 안내문

- 부모에게 보낼 메시지 생성
- 복사 버튼
- LLM 실패 template fallback

### 7. 안전

- UNKNOWN != SAFE
- LLM 판정 금지
- 가족 권한 확인
- 개인정보 최소 수집
- OAuth/DB/API secret 비노출

### 8. 배포

- MariaDB persistent volume
- Docker Compose
- Caddy HTTPS
- `https://yellow.it.kr/`
- 미니 PC `C:\home\dahum`

## P1 - P0가 완전히 끝난 뒤

- 분석 이력 화면
- 가족 연결 해제 UI 고도화
- 안내문 행동 기록
- 여러 가족 그룹 UX 개선
- 데이터셋 버전 관리 화면
- 관리자용 탐지 DB import 도구

## P2 - 해커톤 이후

- 실제 모바일 앱/보안 SDK 연동
- 보호 기기 등록
- 실시간 위험 이벤트
- 자동 알림
- Kakao 자동 메시지 발송
- B2B 통신사/보험/보안업체 연동
- 지속 탐지 DB update/MLOps

## MVP에서 빼야 하는 것

- 자체 악성코드 엔진 개발
- 부모 폰 상시 모니터링
- 복잡한 RBAC
- Kubernetes/다중 서버 등 과한 인프라
- 자동 Kakao 메시지
- 검증되지 않은 AI 자동 판정

## 성공 조건

```text
모바일 접속
 -> Kakao/Google 로그인
 -> 가족/부모 선택
 -> 스크린샷/직접 입력
 -> 분석
 -> 위험 근거
 -> 쉬운 설명
 -> 부모 안내문
 -> 복사
```

이 한 사이클이 안정적으로 성공하면 MVP의 핵심이 완성된 것입니다.
