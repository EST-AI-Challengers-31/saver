# 왜 이렇게 설계했는지

## 1. React -> Spring Boot -> FastAPI로 분리한 이유

기획서의 역할 자체가 프론트, 백엔드, AI 파트로 나뉘어 있고 AI 파트는 Python 기반입니다.

그래서:

```text
React       사용자 경험
Spring Boot 인증/권한/DB/공개 API
FastAPI     OCR/RAG/LLM
```

로 경계를 나누었습니다.

장점:
- 브라우저 secret 노출 방지
- AI 교체 시 frontend 영향 감소
- Java 도메인/DB와 Python AI를 독립적으로 개발
- 팀원이 병렬 작업 가능

## 2. 로그인 처리를 Spring Boot에 둔 이유

React가 OAuth token을 직접 장기 관리하면 모바일 웹에서 보안/세션/refresh 처리 코드가 커집니다.

Spring Security를 인증의 중심으로 두면:
- provider callback 한 곳에서 처리
- 가족 권한과 인증 연결 쉬움
- HttpOnly session 사용 가능
- Client Secret을 서버에만 둘 수 있음

## 3. Kakao와 Google identity를 별도 테이블로 둔 이유

한 사람이 여러 로그인 방식을 연결할 가능성을 열어두기 위해서입니다.

`app_user`는 서비스 사용자이고, `oauth_identity`는 로그인 수단입니다.

이 구분으로 provider 교체/추가가 user domain을 흔들지 않습니다.

## 4. 부모/자녀 role을 family_member에 둔 이유

부모/자녀는 절대적인 사용자 타입이 아니라 **관계 속 역할**이기 때문입니다.

이 구조는 향후:
- 엄마/아빠/조부모
- 여러 가족 그룹
- 보호자 역할 확장

을 자연스럽게 수용합니다.

## 5. 가족 초대와 동의를 별도 데이터로 둔 이유

서비스가 보호를 명분으로 감시 서비스가 되지 않게 하기 위해서입니다.

초대/수락/동의가 명시되면:
- 누가 연결했는지
- 언제 연결했는지
- 취소/만료됐는지

를 추적할 수 있습니다.

## 6. LLM을 판정에서 분리한 이유

기획서의 가장 중요한 안전 원칙 중 하나가 LLM hallucination 위험입니다.

그래서:

```text
데이터/규칙/RAG -> 판정
LLM             -> 쉬운 설명
```

으로 분리합니다.

이렇게 하면 설명 모델이 바뀌어도 HIGH/MEDIUM/UNKNOWN의 근거가 유지됩니다.

## 7. UNKNOWN을 별도 상태로 둔 이유

제공 탐지 데이터가 전체 세상을 포함하지 않으므로 `검색 안 됨 = 안전`은 틀린 결론입니다.

따라서 UNKNOWN은 제품 안전의 핵심 상태입니다.

## 8. MariaDB에 최종 확장 테이블까지 준비한 이유

MVP 이후 자연스럽게 필요한 흐름은:

```text
로그인
 -> 가족
 -> 분석
 -> 행동
 -> 향후 알림
```

입니다.

처음 DB가 분석 결과만 저장하면 로그인/가족 기능을 붙일 때 큰 구조 변경이 필요합니다.

그래서 현재는 테이블 자리를 준비하되, 실제 기능 구현은 우선순위에 따라 제한합니다.

## 9. protected_device를 만들고도 MVP에서 쓰지 않는 이유

향후 실제 모바일 앱/보안 SDK가 연결되면 기기 단위가 필요할 수 있습니다.

하지만 현재 기획의 MVP는 스크린샷 기반이므로 지금 기기 등록을 강제하면 복잡도만 커집니다.

즉 **DB는 확장 가능, UI/기능은 단순**하게 둡니다.

## 10. C:\home\dahum에서 app/runtime을 분리한 이유

Git pull/redeploy와 DB 데이터/secret의 수명은 다릅니다.

```text
app     코드 - 교체 가능
runtime 데이터/secret - 보존 필요
```

분리하면:
- git reset이 DB를 건드리지 않음
- compose rebuild에도 MariaDB 데이터 유지
- `.env` 커밋 위험 감소
- backup 위치 명확

## 11. Caddy를 앞에 둔 이유

사용자는 `https://yellow.it.kr/` 하나만 사용하고 내부 포트는 숨깁니다.

Caddy가:
- HTTPS
- React routing
- Spring API/OAuth routing

을 담당합니다.

MariaDB/FastAPI를 외부에 노출할 이유가 없습니다.

## 12. GitHub Actions는 SSH로 '명령만' 전달하는 이유

운영 DB/secret은 미니PC에 남겨야 합니다.

GitHub Actions가 운영 `.env`를 매번 전송하기보다:

```text
GitHub -> SSH -> mini PC deploy.ps1
```

로 하면 서버가 자기 runtime 환경을 사용합니다.

## 13. 이번 하네스에서 일부러 하지 않은 것

- 프레임워크 내부 세부 구현 코드 강제
- 자동 Kakao 메시지 구현
- 모바일 네이티브 앱 전환
- Redis/Kubernetes 등 해커톤에 과한 인프라
- 임의 threshold 확정
- 임의 LLM provider 고정

이 항목들은 실제 요구/팀 선택 전에 하드코딩하면 오히려 교체 비용이 커지기 때문입니다.
